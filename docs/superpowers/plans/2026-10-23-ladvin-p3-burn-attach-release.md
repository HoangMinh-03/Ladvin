# ladvin Plan 3 — Burn Meter, Attach, Release Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Show what the whole fleet is burning per Claude account (real window utilization where Claude reports it), open live views of remote agents in the user's terminal, and make ladvin installable by strangers (release binaries, checksums, upgrade by hash, README, icon).

**Architecture:**
- **Usage scanning** lives in the shared `protocol` package, so agentd (per host) and the hub (local machine) use the same code. It reads `~/.claude/projects/**/*.jsonl` incrementally and dedupes by `message.id`.
- **Utilization:** agentd records the latest `rate_limit_event` seen from any of its agents (spikes §1). That gives the real 5-hour and 7-day utilization of the host's account.
- **Aggregation:** the hub groups hosts plus the local machine by `oauthAccount.accountUuid`. It caches a snapshot for a statusline script and enforces optional budgets before starting work.
- **Attach** is a pure command builder plus one spawn.
- **Release** is a build script used by both CI and developers.

**Tech Stack:** As before. GitHub Actions for CI and release.

**Spec:** `docs/superpowers/specs/2026-10-23-ladvin-design.md` §10, §12, §13, §15, plus `docs/spikes.md` (rate_limit_event, account identity, transcript format).

## Global Constraints

- Never read or transmit credentials. From `~/.claude.json`, only `oauthAccount.{accountUuid,emailAddress,displayName}` may be read.
- Usage counts: "billable" = input + output + cacheWrite. cacheRead is shown separately and never counted toward budgets.
- Account fallback: if a host has no `oauthAccount`, group it as `host:<alias>` and mark it "account unknown".
- Utilization is shown only when observed. Display the time it was observed (`5h 23% (seen 4 min ago)`). If it has never been observed, show "—", never a guess.
- Budgets are optional, per account: `fiveHourPct`, `sevenDayPct` (from utilization), `fiveHourTokens`, `sevenDayTokens` (billable). While any is exceeded, `ladvin_delegate` and `ladvin_team_start` on that account's hosts are refused with a message naming the budget and how to raise it.
- Attach adapter order (spec §13): `LADVIN_TERMINAL` override → WezTerm (`WEZTERM_PANE`) → tmux (`TMUX`) → macOS Terminal.app → print the command.
- Release assets: `ladvin-agentd-{linux,darwin}-{x64,arm64}` + `SHA256SUMS`, on tag `v<version>`.
- Version for this plan: 0.3.0.

## Review Focus

1. **Transcripts written while the scanner reads them** (partial last line, files rotated or deleted). Expected: the partial line is retried on the next scan; nothing crashes and nothing is counted twice. → Task 1 test.
2. **The same assistant message appears many times in a transcript** (streaming chunks share `message.id`). Expected: it is counted once. → Task 1 test.
3. **A host that is unreachable when `ladvin_burn` runs.** Expected: that row says unreachable, the rest still renders, and budget checks for other accounts still work. → Task 3 test.
4. **Attach to a task whose tmux view has already closed, or a task id from another project.** Expected: a clear message, and no terminal pane flashing open and shut. → Task 4 test.
5. **add-host on a host whose agentd binary is identical.** Expected: no upload and no restart. A different binary while agents run → the upload still happens, the restart is deferred, and the user is warned. → Task 5 test.

### Task 1: Shared usage scanner

**Files:** Create `packages/protocol/src/usage.ts` and export it from `index.ts`. Test: `packages/protocol/test/usage.test.ts`.

**Interfaces — Produces:**
- `type UsageEvent = { ts: number; id: string; usage: Usage }`
- `type ScanState = { files: Record<string, number /* byte offset */>; seen: string[] /* message ids, last 7 days */; events: UsageEvent[] }`
- `scanTranscripts(root: string, state: ScanState, now: number): ScanState`
  - Walks `root` recursively for `*.jsonl`.
  - Reads each file from its offset up to the last complete line only, so a partial tail line is left for next time.
  - Keeps lines where `type === "assistant"` and `message.usage` and `message.id` are present.
  - Dedupes by `message.id` against `seen`.
  - Drops events and seen ids older than `now - 7d`.
  - A file shorter than its stored offset is re-read from 0.
  - Missing files are dropped from `files`.
- `windowSums(events: UsageEvent[], now: number): { last5h: Usage; last7d: Usage; billablePerMin15: number }`. The last field is billable tokens per minute over the last 15 min.
- `readAccount(home: string): { accountUuid: string; email?: string; name?: string } | null`. Reads `<home>/.claude.json` → `oauthAccount`. Unreadable or missing → `null`.
- `billable(u: Usage): number`
- [ ] **Step 1: Failing tests** (temp dir with a hand-written `projects/a/s1.jsonl` and `projects/a/sub/s2.jsonl`):
  - Two assistant lines with the same `message.id` and one with a different id → 2 events (**Review Focus 2**).
  - A partial last line (no `\n`) is not consumed. After appending the rest, the next scan picks it up exactly once (**Review Focus 1**).
  - A file truncated after a scan is re-read from 0 without double counting ids already seen.
  - A deleted file → scanning does not throw.
  - Events older than 7 days are dropped.
  - `windowSums` over events at now−1h (in 10, out 5, cw 20, cr 100) and now−6h → `last5h` = `{input:10, output:5, cacheWrite:20, cacheRead:100}`; `last7d` includes both.
  - `readAccount` returns the uuid and email from a fixture `.claude.json` that also contains a fake `"primaryApiKey"`. The result has no other keys. It returns `null` when the file is missing.

### Task 4: Attach

**Files:** Create `packages/hub/src/attach.ts`, `packages/hub/src/tools/attach.ts`, `commands/attach.md`. Test: `packages/hub/test/attach.test.ts`.

**Interfaces — Produces:**
- `sshAttachArgv(alias: string, taskId: string): string[]` → `["ssh", ...(-F cfg), "-t", alias, "tmux attach -t ladvin-<taskId>"]`.
- `type AttachPlan = { kind: "spawn"; command: string; args: string[] } | { kind: "print"; command: string }`
- `attachPlan(env: Record<string,string|undefined>, platform: NodeJS.Platform, argv: string[]): AttachPlan`:
  - `LADVIN_TERMINAL` ∈ {wezterm, tmux, terminal, print} forces the adapter.
  - WezTerm → `wezterm cli split-pane -- <argv>`.
  - tmux → `tmux split-window <shell-quoted argv joined>`.
  - darwin → `osascript -e 'tell application "Terminal" to do script "<escaped cmd>"' -e 'tell application "Terminal" to activate'`.
  - Otherwise print.
- `ladvin_attach({task_id})`, where `task_id` may also be `"all"`:
  - Resolves the host as delegate does, and refuses tasks owned by another project.
  - Checks on the remote that `tmux has-session -t ladvin-<id>` succeeds. If not, it returns `The live view for <id> has closed (it closes 10 minutes after the task ends). Read the result with ladvin_report.` (**Review Focus 4**).
  - Spawns the plan detached, or returns the command to run.
  - `all` attaches every running or idle task of this project.

### Task 5: Upgrade by binary hash

**Files:** Modify `packages/hub/src/setup/add-host.ts`. Test: `packages/hub/test/add-host.test.ts`.

**Interfaces — Produces:**
- `addHost` computes the sha256 of the local binary.
- Before uploading, it runs `posix("sha256sum ~/.ladvin/bin/ladvin-agentd 2>/dev/null || shasum -a 256 ~/.ladvin/bin/ladvin-agentd 2>/dev/null")`. If the hash matches, it skips the upload and prints the line `✓ ladvin-agentd already up to date`.
- After connecting, if `hello.binarySha256` differs from the local hash, it calls `shutdown` (not forced):
  - success → reconnect, printing `✓ restarted agentd on the new binary`;
  - refusal (agents running) → print `⚠ agentd keeps running the old binary until its N agent(s) finish; run /ladvin:add-host <alias> again afterwards.`
- `ConnectInfo` gains `binarySha256?`.
- [ ] **Step 1: Failing tests** (**Review Focus 5**):
  - Remote hash equal and hello hash equal → no upload, no `shutdown` call.
  - Remote hash different → upload. Hello hash still old and `shutdown` rejects with "2 agents running" → the warning line appears and the host is still saved.
  - Hello hash old and `shutdown` succeeds → reconnect, and the line `restarted agentd` appears.
- [ ] **Step 2: Run** — FAIL. **Step 3: Implement.** **Step 4: Run** — PASS.
- [ ] **Step 5: Commit** — `feat(hub): add-host upgrades by binary hash, restarts only when idle`
